# Установка исправлений авторизации и данных

Изменения подготовлены локально. Миграция рабочей базы, публикация сервера,
мобильная сборка и настройки облачного bucket автоматически не выполнялись.
Подключение Google Play Billing не добавлялось.

## Порядок обновления

1. Сделайте резервную копию PostgreSQL и проверьте текущую ревизию командой
   `alembic current` из каталога `backend` в окружении нужного сервера.
2. Примените `alembic upgrade head` перед запуском обновлённого backend.
   Новая ревизия `c62026102701` следует за `b88ee1c91032`. Не используйте
   `alembic stamp head` вместо выполнения новой миграции.
3. Выпустите обновлённое мобильное приложение вместе с backend: старое приложение
   не умеет получать временные ссылки на защищённые вложения чата.
4. После обновления пользователи должны войти заново. Токены старого формата
   отклоняются, поскольку раньше их можно было получить через ошибку проверки email.

Миграция добавляет время первого использования подписки к пользователю и время
создания замера веса. Исторические ISO-даты веса приводятся к `YYYY-MM-DD`,
исходное время ISO-записей сохраняется в `created_at`, текущий вес пересчитывается.
Для старых записей только с датой точное время внесения неизвестно; при равенстве
даты и времени используется ID как стабильный порядок. Записи не удаляются.
Тренерам с ранее начатой подпиской новый бесплатный период не выдаётся.

## Облачное хранилище

Для `STORAGE_PROVIDER=s3`, `r2` или `gcs` bucket с файлами должен запрещать
анонимное чтение. Отключите публичный bucket/CDN-домен и удалите публичные
разрешения на объекты, если они были настроены. Ранее опубликованные файлы
нужно также убрать из публичного CDN-кэша. Изменение кода само по себе не отменяет
публичные разрешения и сохранённые копии файлов.

Сервисному аккаунту backend нужны права чтения и записи объектов. Приложение
получает ссылки на API, backend проверяет владельца загрузки или участника
переписки и передаёт вложения потоком с поддержкой HTTP Range. Прямые старые
облачные ссылки из сообщений преобразуются в ссылки API. Сохраните
`STORAGE_PUBLIC_BASE_URL` / `GCS_PUBLIC_BASE_URL` как прежний адрес для распознавания
исторических ссылок, даже после отключения публичного доступа.

Аватары остаются публичными через отдельный API-маршрут. Для облачных аватаров
сервер выдаёт короткую подписанную ссылку, поэтому публичное чтение всего bucket
для них не требуется. Для GCS сервисный аккаунт должен уметь подписывать ссылки.

Временная ссылка вложения действует 10 минут, привязана к одному файлу и сессии.
Она позволяет открыть файл тому, кто получил эту ссылку, в течение её срока
действия. На каждом запросе backend повторно проверяет право доступа. Сброс
пароля отзывает access-, refresh- и media-токены. Токены в query string не следует
сохранять в журналах reverse proxy.

## Локальные проверки

Из `backend`:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют SQLite в памяти и тестовый ключ, не обращаются к рабочей
PostgreSQL, SMTP или облаку. SQL новой миграции проверяется в offline-режиме;
применение миграции к настоящей PostgreSQL и блокировки конкурентных транзакций
нужно проверить на отдельной staging-базе перед выпуском.

Из `expo`:

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run test:regressions
```

На Android/iOS дополнительно проверьте вход без сети, восстановление сети,
открытие карточки клиента при загрузке данных, запись и удаление веса,
фото/голосовые/видео в чате и перемотку видео. Проверки Node не заменяют запуск
на устройстве и реальную интеграцию с выбранным облачным хранилищем.
