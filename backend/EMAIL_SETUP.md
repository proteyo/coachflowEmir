# Подтверждение почты и восстановление пароля

Аккаунт остаётся неподтверждённым, если отправить код не удалось. Повторная
отправка кода и успешное подтверждение позволяют войти без новой регистрации.
Отключать проверку email или вручную подтверждать произвольные адреса не нужно.
Обновление также закрывает выдачу токенов для уже подтверждённого email без
проверки кода: для такого аккаунта необходимо войти обычным способом с паролем.

## Render Free

Render Free блокирует исходящий SMTP на портах 25, 465 и 587:
https://render.com/docs/free

Для такого окружения добавлен транспорт Resend через HTTPS, который используется
и для кода подтверждения, и для восстановления пароля. SMTP остаётся доступным
для окружений, в которых эти порты разрешены. По умолчанию выбран SMTP.

## Включение HTTPS-отправки

1. Настройте аккаунт Resend и отправителя с подтверждённым доменом.
2. Создайте API-ключ отправки писем.
3. После публикации обновлённого backend задайте в Render Environment:

```env
EMAIL_PROVIDER=resend
RESEND_API_KEY=your_server_side_key
EMAIL_FROM=CoachFlow <no-reply@your-verified-domain.com>
EMAIL_TIMEOUT_SECONDS=20
FRONTEND_RESET_URL=coachflow://reset-password
```

`RESEND_API_KEY` хранится только в backend. В Expo или `EXPO_PUBLIC_*` он не нужен.
Не вставляйте пример адреса из документации: укажите своего подтверждённого
отправителя. Тестовый `onboarding@resend.dev` отправляет письма только на почту
владельца аккаунта Resend; для регистрации пользователей с другими адресами
необходим свой подтверждённый домен.

Документация API: https://resend.com/docs/api-reference/emails/send-email
Ограничение тестового отправителя:
https://resend.com/docs/knowledge-base/403-error-resend-dev-domain

Обновление одних переменных у старого backend не включает новый транспорт:
необходимо опубликовать этот код. Это отдельное обновление почты не изменяет
схему базы данных и не требует миграций. Эта инструкция не выполняет deploy,
настройку DNS или отправку настоящих писем автоматически.

После обновления откройте «Подтвердить почту» в приложении и запросите новый код.
Проверьте папки «Входящие» и «Спам». Если сообщение не ушло, посмотрите логи
отправки backend: для HTTPS-транспорта там выводится только HTTP-статус ошибки,
без ключа API и кода подтверждения.
